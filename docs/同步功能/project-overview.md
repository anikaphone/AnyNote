# AnyNote 手动同步：整体说明

状态：客户端、服务端和在线管理已实现。当前执行证据、实现细节与剩余人工验收见 [implementation-report.md](implementation-report.md)；进度见 [TODO.md](TODO.md)。

## 1. 目标与已确认决策

保留原生 Windows 客户端，在“云同步”菜单中提供登录/注册、全库上传、全库下载、在线管理。所有笔记传输由用户手动触发；自动登录不等于自动同步。

| 项目 | 决策 |
| --- | --- |
| 同步内容 | 通过 HTTPS 传输 JSON 表示的完整笔记数据，RTF 用 Base64 包装；不传输本地加密数据库文件 |
| 服务端信任 | 用户确认服务端可读取标题、结构和 RTF；这不是端到端加密 |
| 节点身份 | 新增跨设备唯一的 `sync_id`；现有 `id`、`parent_id` 保留供本地数据库和界面使用 |
| 目录操作 | 同步、覆盖、删除作用于整个子树；缺失祖先自动补齐；确认框列出影响数量 |
| 库身份 | 新增单行 `uid` 表，保存固定 16 位字符串；不以文件名识别库 |
| 本地配置 | INI 平滑迁移为 JSON，保留全部原设置；提供 UID 到文件名的映射和独立路径信息 |
| TLS | 自签证书，有效期按 100 年配置；客户端必须验证信任、有效期和主机名 |
| 技术栈 | C++20/Win32/SQLite3MC；客户端新增 nlohmann/json、libcurl；服务端纯 Go、SQLite |

这里的“全库”指当前笔记库的全部笔记及结构，不包括所有已登记的笔记库，也不上传本机路径、窗口设置、账户凭据或数据库密码。全量覆盖删除目标端独有笔记；覆盖前明确显示新增、修改、删除数量。

## 2. 现有项目基线

本次已检查源码：实际客户端目录为 `src/AnyNoteClient/`。`Database` 使用 SQLite3MC AES-256-CBC、WAL；`NoteRepository` 管理 `nodes` 与 `node_contents`，节点是自增整数 ID，内容是 RTF BLOB，并存有本地检索用 `plain_text`。`VaultManager` 当前读写 `anynote.ini`。`MainWindow::SaveActiveNote()` 是保存当前编辑的入口。

目前没有本方案的服务端、协议、UID、`sync_id`、`content_hash` 和同步界面。现有原生存储、代码块、表格、搜索、大纲能力均需回归。开发不能按旧目录 `src/storage/` 等直接添加文件。

## 3. 用户流程

### 3.1 账户与入口

“云同步”菜单始终可见，未登录时只开放登录/注册。初次运行不联网、不提示开启同步。登录窗口含登录、注册、改密三个标签；改密仅登录后可用。服务器地址和证书路径在登录窗口的“连接设置”中配置，默认地址为空。

- 登录：账号、密码、记住密码、自动登录。勾选自动登录同时勾选记住密码；取消记住密码同步取消自动登录。
- 注册：账号、密码、注册按钮；成功后转登录页，不自动上传任何笔记。
- 改密：旧密码、新密码；成功后注销所有设备的会话，清除当前设备保存的旧凭据，返回登录页。
- 登录后显示账号与“退出登录”；退出清除会话、保存密码和自动登录选项。切换账号必须先退出，清除旧账号的云端列表缓存。
- 自动登录失败只显示状态，保留本地编辑能力；不循环弹窗。没有开启自动登录时启动不联网。

账号默认 3–32 个 ASCII 字母、数字、下划线，匹配 `[A-Za-z0-9_]{3,32}`，按小写规范化确保大小写不产生重复账号；密码 8–128 个 Unicode 字符且 UTF-8 不超过 512 字节，允许空格、不 trim、不做 Unicode 归一化。客户端和服务端均验证。

### 3.2 全库上传

保存当前编辑成功后读取远端版本、生成影响预览。显示“是否将本笔记库全量笔记上传？”以及账号、服务器、库名/UID、将删除的远端独有节点数量。确认后禁止客户端业务操作，显示进度和取消按钮。服务端一次事务提交；成功后更新版本和在线列表。失败保留本地数据与原远端库。

### 3.3 全库下载

仅下载当前 UID 对应远端库，不根据同名库猜测。远端不存在则提示到在线管理选择库。先确认目标库，再二次确认“将覆盖本地全部笔记，包含删除本地独有笔记”；备份成功后才允许写入。下载期间禁止业务操作，成功刷新编辑器、树、搜索、大纲，清空旧文档撤销栈。备份或保存失败则停止。

### 3.4 在线管理

独立原生窗口，两个标签：笔记库列表、库详情。列表默认显示 UID、数据库名、创建时间、更新时间、备注；右键包含查看详情、下载到本地、删除、修改备注。备注只保存在服务端，不写入本地笔记库或配置。

下载到本地：同 UID 默认选定已登记的本地文件，但仍确认覆盖；不同 UID 同文件名时要求另存为，不静默覆盖。没有本地库时选择路径和本地加密密码（可选择不加密），下载完成才登记。相同 UID 有多个本地副本时要求用户选定主副本，不自动选第一个。

库详情：返回按钮、远端节点树、差异表。树使用状态图标和文字区分标题、内容、位置、时间差异。差异表显示本地与远端的并集，至少显示节点 ID、标题、父 ID、更新时间、差异类型；ID 不同时分别标注本地/远端。远端树不能显示本地独有节点，这类节点仍出现在差异表中。

树右键“同步到本地”“删除”“详情”；差异表右键“删除”“上传覆盖”“下载覆盖”。删除始终只删远端；远端不存在时禁用删除，源端不存在时禁用对应上传/下载。“详情”展示 UID、sync_id、两侧 ID、时间、哈希、RTF 大小和差异类型，不执行 RTF 内嵌对象。

成功后重新比较再清除标记，不能仅因 HTTP 成功就移除行。远端删除后本地仍存在的节点成为“仅本地”，继续显示，避免掩盖差异。

## 4. 边界与默认约束

第一版不实现自动同步、定时同步、文本合并、多人协作、网页编辑器、分享、邮件找回密码、客户端历史版本浏览、断点续传。服务器备份和本地覆盖备份是故障恢复措施，不是同步历史。

同一 UID 表示同一个逻辑库。复制文件保留 UID 和 sync_id；“作为新库导入”必须生成新 UID 及全部新 sync_id。旧版本的多个副本需选一份作为初始来源上传，其他副本备份后下载建立共同身份；不能按相同 id 自动推断为同一笔记。

服务端单进程、单机 SQLite 部署，首个验收目标 Linux amd64；Windows amd64 为开发环境。数据目录放本地磁盘。第一版不支持多个服务实例共享同一个 SQLite 文件。

默认限制：单篇 RTF 16 MiB、单库原始 RTF 合计 128 MiB、单库 20,000 节点、树深 128、单账号 100 库/1 GiB 原始 RTF、单个 JSON 请求 192 MiB。通过服务端配置调整，并在客户端同步前展示限制；上线前按实测收紧或放宽，不宣称已经验证性能。
